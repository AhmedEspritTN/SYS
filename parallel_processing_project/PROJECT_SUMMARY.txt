KEY_CONCEPTS_COVERED = """
CONCEPTS EXPLAINED & IMPLEMENTED

1. INTERPROCESS COMMUNICATION (IPC)
   - Pipes: One-way/bidirectional process connection
   - Queues: Thread-safe multi-producer/consumer messaging
   - Shared Memory: Direct memory access with synchronization
   - Use Cases: Parent-child communication, task distribution, data sharing

2. SYNCHRONIZATION
   - Semaphores: Resource counting and mutual exclusion
   - Binary Semaphore: Acts as a lock
   - Counting Semaphore: Manages multiple resources
   - Mutex Locks: Critical section protection
   - Context Managers: Safe resource handling

3. CLASSIC PROBLEMS
   
   Dining Philosophers (Dijkstra's Algorithm)
   ├─ Problem: Deadlock with circular resource dependencies
   ├─ Solution: State machine + careful semaphore ordering
   ├─ States: THINKING → HUNGRY → EATING
   └─ Result: Deadlock-free, fair allocation
   
   Sleeping Barber (Producer-Consumer with Constraints)
   ├─ Problem: Resource management with waiting room capacity
   ├─ Solution: Semaphores for customer queue and barber availability
   ├─ Capacity: Limited waiting chairs (default: 3)
   └─ Result: Fair service, no starvation
   
   Producer-Consumer (Bounded Buffer)
   ├─ Problem: Synchronization on shared bounded resource
   ├─ Solution: Two semaphores (empty slots, full slots)
   ├─ Synchronization: Binary signaling between producers/consumers
   └─ Result: No overflow/underflow, FIFO ordering

4. MULTIPROCESSING vs MULTITHREADING
   
   Multiprocessing (CPU-bound)
   ├─ True parallelism (multiple cores)
   ├─ No GIL (Global Interpreter Lock)
   ├─ Higher startup cost (~10-50MB per process)
   ├─ Slower IPC (must use queues/pipes)
   ├─ Typical Speedup: 2-4x on 4-core system
   └─ Use: Heavy computations, image processing
   
   Multithreading (I/O-bound)
   ├─ Concurrent execution (one core, many I/O waits)
   ├─ Shared memory (careful synchronization needed)
   ├─ Low startup cost (~1-2MB per thread)
   ├─ Fast IPC (shared memory)
   ├─ Typical Speedup: 3-5x for network I/O on 4-core
   └─ Use: Network requests, file I/O, database queries

5. PERFORMANCE METRICS
   - Throughput: Tasks/second, Frames/second, MB/second
   - Latency: Time per operation (milliseconds)
   - Speedup: Sequential_Time / Parallel_Time
   - Efficiency: Speedup / Number_of_Workers
   - Scalability: How speedup changes with worker count
"""
